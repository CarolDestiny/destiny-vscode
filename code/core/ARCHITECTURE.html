模块职责

每个模块保持小接口和深实现。

错误管理

error

  • 错误码全部是 TypeCode 常量
  • 等级查询返回 0..4 或 -1
  • 先记录，再投递错误事件
线程管理

thread

  • 公开 destiny::Thread
  • heavy / normal / light 只表达语义
  • 编译期固定命名槽位，不暴露任意 thread_local
诊断采集

diagnostic

  • 发行版采集必要上下文
  • 调试构建可追加更多信息
  • 不依赖 log、不创建线程
内存管理

memory

  • 固定块与变长块自定义分配器
  • Allocation 句柄携带 owner/generation
  • 预申请、回收、泄露检查由独立 light worker 维护
日志管理

log

  • destiny::Log 无参 builder
  • 非阻塞 MPMC，固定一个 log light worker
  • log/index/slow 三文件职责分离
最终策略

slow lane

  • 队列满、内存失败都立即降级
  • early 与 slow 都加锁写 slow.destiny
  • slow writer 失败触发 core unload

Log 写入路径

原始记录不改码；故障通过新增 warning 记录表达。

正常路径非阻塞 try_push
Log()自动采集 diagnostic
→

→

→
writeLogIndex + UTC 秒
→

→
log + index随后投递 error
慢车道队列满或内存失败

落盘协议

长度字段保护后续内容；user 只复制、不解析。

文件头与记录

[magic:uint64]
[fileTypeCode:uint64]

[DestinyRecordCode:uint64]
[recordLength:uint64]
[LogIndex:uint64]  # 低 32 位有效
[errorTime:uint64] # UTC Unix 秒
[Log section]
recordLength = 其后所有字节，不包含前 16 字节记录头。

Log 区段（提交格式）

[sectionType:uint64]
[sectionLength:uint64]
[diagnosticLen:uint64]
[userLen:uint64]
[diagnostic bytes]
[user bytes]
sectionLength = 16 + diagnosticLen + userLen；空文本合法。

index.destiny · 64 字节

slot[0] LogIndex
slot[1] errorTime
slot[2] level
slot[3] logOffset
slot[4] recordLength
slot[5] reserved0
slot[6] reserved1
slot[7] reserved2
只索引 log.destiny；slow.destiny 使用同格式但不索引。

日期目录

YYYY-MM-DD/   # UTC
  log.destiny
  index.destiny
  slow.destiny
文件名是别名，唯一身份由 TypeCode 和文件头编码确定。

生命周期

memory 最后收口所有权；early/slow 最后关文件。

启动onload() → bool
early writer → slow.destiny→ error→ thread + 固定槽位→ memory + 维护 worker→ normal log + 一个 light worker→ 绑定 diagnostic
关闭反序排空
停止 log 接收并排空→ 停止 error 事件→ thread 静默→ memory 回收 / 查漏→ join workers→ 关闭 early/slow

关键决策速览

为什么 Log 不公开等级和写入结果？

等级由 error 解析，写入结果由调用方无法处理；隐藏这两项能保持 Log 接口深而小，避免调用方依赖 normal/slow/early 的内部布局。

为什么 early writer 也写 slow.destiny？

两者都只需要在最底层故障时加锁写入，复用一个文件和行为可以减少启动期依赖与恢复分支。

为什么 memory 最后收口？

日志、错误和用户 worker 可能仍持有需要追踪的 Allocation；先停止产生工作，再由 memory 清账、回收和查漏，最后 join 线程。
